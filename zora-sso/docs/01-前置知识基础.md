# 01-前置知识基础

## 概述

本章节介绍学习 SSO（单点登录）技术之前需要掌握的基础知识。这些概念是后续理解 OAuth 2.0、OpenID Connect 和 Keycloak 的前提。

## 1.1 认证与授权的区别

### 核心概念

| 概念 | 定义 | 回答的问题 |
|------|------|------------|
| **认证 (Authentication)** | 验证用户身份的过程 | "你是谁？" |
| **授权 (Authorization)** | 决定用户可以访问哪些资源的过程 | "你能做什么？" |

### 生活中的类比

```
┌─────────────────────────────────────────────────────────────────┐
│                        机场安检流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  认证 (Authentication):                                        │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  安检员检查你的身份证                                      │   │
│  │  确认你就是你本人                                         │   │
│  │  "你是谁？" → 确认身份                                    │   │
│  └─────────────────────────────────────────────────────────┘   │
│                           ▼                                    │
│  授权 (Authorization):                                         │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  根据你的机票和目的地                                     │   │
│  │  决定你可以进入哪个登机口                                 │   │
│  │  "你能去哪个登机口？" → 授予权限                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 在 Web 应用中的体现

```
┌─────────────────────────────────────────────────────────────────┐
│                    Web 应用中的认证与授权                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  认证阶段：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  用户输入用户名和密码                                     │   │
│  │  服务器验证凭证是否正确                                    │   │
│  │  验证通过后创建会话 (Session)                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                           ▼                                    │
│  授权阶段：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  用户尝试访问 /admin 页面                                 │   │
│  │  系统检查用户是否具有 ADMIN 角色                          │   │
│  │  有权限 → 允许访问                                        │   │
│  │  无权限 → 拒绝访问                                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 重要区别

1. **顺序**：先认证，后授权
2. **目的**：认证确认身份，授权决定权限
3. **实现**：认证通常使用密码/生物识别，授权通常使用角色/权限

## 1.2 Session 与 Cookie 机制

### 什么是 Session？

Session（会话）是服务器端存储用户状态的一种机制。

```
┌─────────────────────────────────────────────────────────────────┐
│                      Session 工作原理                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  浏览器                      服务器                             │
│     │                          │                                │
│     │──── GET /index ────────▶│                                │
│     │                          │  创建 Session ID              │
│     │◀─── 302 + Set-Cookie ───│  存储在服务器内存/数据库        │
│     │     (JSESSIONID=abc)    │  session:abc = {user: "tom"}  │
│     │                          │                                │
│     │──── GET /index ────────▶│                                │
│     │     Cookie: JSESSIONID  │  根据 Session ID               │
│     │     =abc                │  找到用户信息                  │
│     │◀─── 200 OK (个性化) ────│  返回用户相关数据              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Session 的特点

| 特性 | 说明 |
|------|------|
| 存储位置 | 服务端（内存、数据库、Redis） |
| 数据大小 | 理论上无限制（实际受服务器限制） |
| 安全性 | 客户端只存储 Session ID，不存储敏感数据 |
| 生命周期 | 可以设置过期时间，支持续期 |

### 什么是 Cookie？

Cookie 是浏览器存储少量数据的一种机制，由服务器通过 HTTP 响应头设置。

```
┌─────────────────────────────────────────────────────────────────┐
│                       Cookie 工作原理                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  HTTP 响应（服务器 → 浏览器）：                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  HTTP/1.1 200 OK                                        │   │
│  │  Set-Cookie: sessionId=abc123; Path=/; HttpOnly        │   │
│  │  Set-Cookie: theme=dark; Max-Age=2592000               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  HTTP 请求（浏览器 → 服务器）：                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  GET /index HTTP/1.1                                    │   │
│  │  Cookie: sessionId=abc123; theme=dark                  │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Cookie 的属性

| 属性 | 说明 | 示例 |
|------|------|------|
| `Name` | Cookie 名称 | `JSESSIONID` |
| `Value` | Cookie 值 | `abc123def456` |
| `Domain` | 生效域名 | `.example.com` |
| `Path` | 生效路径 | `/` |
| `Expires/Max-Age` | 过期时间 | `Max-Age=3600`（1小时） |
| `Secure` | 仅 HTTPS 传输 | `Secure` |
| `HttpOnly` | 禁止 JavaScript 访问 | `HttpOnly` |
| `SameSite` | 跨站策略 | `SameSite=Lax` |

### SameSite 属性详解

```
┌─────────────────────────────────────────────────────────────────┐
│                      SameSite 属性值                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  SameSite=Strict                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  最严格： Cookie 只在同站请求中发送                       │   │
│  │  优点：最安全                                            │   │
│  │  缺点：用户从外部链接访问时需要重新登录                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  SameSite=Lax                                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  中等：导航安全请求时发送（如点击链接）                   │   │
│  │  优点：平衡安全性和用户体验                               │   │
│  │  缺点：部分跨站请求不发送 Cookie                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  SameSite=None                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  最宽松：允许跨站请求时发送                               │   │
│  │  必须配合 Secure（仅 HTTPS）使用                         │   │
│  │  缺点：容易受到 CSRF 攻击                                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Session Cookie 的最佳实践

```java
// 设置 Session Cookie 的最佳实践
public class SessionCookieConfig {
    
    public static Cookie createSessionCookie(String sessionId) {
        Cookie cookie = new Cookie("SESSION_ID", sessionId);
        
        // 安全属性
        cookie.setSecure(true);           // 仅 HTTPS
        cookie.setHttpOnly(true);         // 禁止 JS 访问
        cookie.setSameSite("Lax");        // 平衡安全与体验
        
        // 作用域
        cookie.setPath("/");              // 整个站点有效
        cookie.setDomain(null);           // 仅当前域名
        
        // 过期时间
        cookie.setMaxAge(3600);           // 1小时
        
        return cookie;
    }
}
```

## 1.3 HTTP 重定向与状态码

### 什么是重定向？

重定向是服务器指示浏览器跳转到另一个 URL 的机制。

```
┌─────────────────────────────────────────────────────────────────┐
│                       HTTP 重定向流程                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  浏览器 ──────▶  服务器 A ──▶  重定向 ──▶  浏览器 ──▶  服务器 B │
│                           │                                     │
│                      302 Found                                  │
│                      Location: /new-url                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 重定向状态码

| 状态码 | 名称 | 说明 | 常见用途 |
|--------|------|------|----------|
| 301 | Moved Permanently | 永久重定向 | 域名迁移、URL 规范化 |
| 302 | Found | 临时重定向 | 负载均衡、A/B 测试 |
| 303 | See Other | 临时重定向 | POST → GET 重定向 |
| 304 | Not Modified | 缓存响应 | 浏览器缓存 |
| 307 | Temporary Redirect | 临时重定向 | 保持请求方法 |
| 308 | Permanent Redirect | 永久重定向 | 保持请求方法 |

### OAuth 2.0 中的重定向

OAuth 2.0 授权流程大量使用重定向：

```
┌─────────────────────────────────────────────────────────────────┐
│                  OAuth 2.0 授权码流程中的重定向                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 用户点击登录                                                  │
│     ┌─────────────────────────────────────────────────────────┐ │
│     │  浏览器 ──▶ 应用服务器：GET /login                      │ │
│     │  应用服务器 ◀── 302 Location: https://auth-server/      │ │
│     │              authorize?client_id=xxx&redirect_uri=...  │ │
│     └─────────────────────────────────────────────────────────┘ │
│                           ▼                                     │
│  2. 授权服务器认证后回调                                          │
│     ┌─────────────────────────────────────────────────────────┐ │
│     │  授权服务器 ──▶ 浏览器：302 Location:                   │ │
│     │              https://app/callback?code=xxx&state=xxx   │ │
│     └─────────────────────────────────────────────────────────┘ │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 重定向注意事项

1. **Location 头**：必须使用完整的 URL（包含协议和域名）
2. **相对路径**：部分状态码支持，302/303 不支持
3. **POST 请求后重定向**：使用 303 而非 302
4. **SEO 影响**：301 传递 PageRank，302 不传递

## 1.4 HTTPS 基础

### 为什么需要 HTTPS？

```
┌─────────────────────────────────────────────────────────────────┐
│                    HTTP vs HTTPS 对比                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  HTTP (明文)                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  用户 ──▶ [明文传输] ──▶ 服务器                          │   │
│  │  密码: 123456  →  容易被窃听                             │   │
│  │  Cookie: abc  →  容易被劫持                             │   │
│  │  Session ID   →  容易被伪造                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  HTTPS (加密)                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  用户 ──▶ [TLS 加密] ──▶ 服务器                         │   │
│  │  所有数据都被加密传输                                    │   │
│  │  防止中间人攻击                                           │   │
│  │  验证服务器身份                                           │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### TLS/SSL 握手过程

```
┌─────────────────────────────────────────────────────────────────┐
│                       TLS 握手过程                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  客户端                                              服务器      │
│     │                                                  │         │
│     │──────── ClientHello ──────────────────────────▶│         │
│     │      (支持的密码套件、随机数)                      │         │
│     │                                                  │         │
│     │◀────── ServerHello ─────────────────────────────│         │
│     │      (选定密码套件、随机数、证书)                   │         │
│     │                                                  │         │
│     │──────── 验证证书 ──────────────────────────────▶│         │
│     │      (检查证书链、有效期、域名)                     │         │
│     │                                                  │         │
│     │──────── 预主密钥 (加密) ────────────────────────▶│         │
│     │                                                  │         │
│     │◀────── 握手完成 ─────────────────────────────────│         │
│     │      (生成会话密钥)                                │         │
│     │                                                  │         │
│     │======== 加密通信开始 ──────────────────────────▶│         │
│     │                                                  │         │
└─────────────────────────────────────────────────────────────────┘
```

### 证书类型

| 类型 | 说明 | 用途 |
|------|------|------|
| DV (Domain Validation) | 域名验证 | 个人站点、测试环境 |
| OV (Organization Validation) | 组织验证 | 企业官网 |
| EV (Extended Validation) | 扩展验证 | 金融、电商 |

### 自签名证书 vs CA 证书

```
┌─────────────────────────────────────────────────────────────────┐
│                     证书对比                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  自签名证书                                                     │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  openssl req -x509 -newkey rsa:2048 -keyout key.pem     │   │
│  │            -out cert.pem -days 365 -nodes               │   │
│  │  • 免费                                                   │   │
│  │  • 浏览器不信任                                           │   │
│  │  • 适用于开发和测试                                       │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  CA 证书                                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  • 需要向 CA 申请（Let's Encrypt 免费）                  │   │
│  │  • 浏览器信任                                             │   │
│  │  • 适用于生产环境                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### OAuth 2.0 为什么必须使用 HTTPS？

1. **保护 Authorization Code**：防止被窃听
2. **保护 Client Secret**：防止泄露
3. **保护 Token**：防止被截获
4. **防止 MITM 攻击**：防止中间人替换 Token

## 1.6 实践任务

### 任务 1：理解 Session 工作机制

```java
// 练习：手动实现简单的 Session 管理
public class SimpleSessionManager {
    
    private Map<String, Session> sessions = new ConcurrentHashMap<>();
    
    public String createSession(User user) {
        // 1. 生成唯一的 Session ID
        String sessionId = UUID.randomUUID().toString();
        
        // 2. 创建 Session 对象
        Session session = new Session();
        session.setId(sessionId);
        session.setUser(user);
        session.setCreatedAt(Instant.now());
        session.setLastAccessedAt(Instant.now());
        
        // 3. 存储到内存
        sessions.put(sessionId, session);
        
        return sessionId;
    }
    
    public Session getSession(String sessionId) {
        Session session = sessions.get(sessionId);
        if (session != null && !session.isExpired()) {
            session.setLastAccessedAt(Instant.now());
            return session;
        }
        return null;
    }
    
    public void invalidateSession(String sessionId) {
        sessions.remove(sessionId);
    }
}
```
