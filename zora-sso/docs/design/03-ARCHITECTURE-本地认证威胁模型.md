# 本地认证 POC 威胁模型

| 威胁 | 控制措施 |
|---|---|
| 开放重定向 | 客户端和回调 URI 预注册，完整字符串匹配，拒绝通配符 |
| CSRF 登录劫持 | 登录事务绑定独立随机 CSRF Token，并设置短 TTL |
| Session 固定 | 登录成功生成新的 256 bit Session ID |
| Code 重放 | Code 服务端仅存摘要，短期有效且原子单次消费 |
| Code 串用 | 绑定客户端、回调 URI、用户和中央 Session |
| 凭证填充 | 按规范化用户名和来源地址组合进行内存限流 |
| 用户枚举 | 未知用户、错误密码和禁用账号使用统一失败响应 |
| 密码泄漏 | 只接受 PBKDF2 哈希，密码使用后清空字符数组 |
| Cookie 窃取 | `HttpOnly`、`SameSite=Lax`；生产模式强制 `Secure` |
| XSS | HTML 动态值转义，设置严格 CSP 和禁止 frame |
| 日志泄漏 | 不记录密码、Cookie、Code、CSRF Token 和客户端密钥 |
| 生产误用 | 本地模式显式启用；生产环境默认拒绝启动 |

## 剩余风险

- 内存状态无法跨节点共享，进程退出会使全部会话失效。
- 来源地址限流可能受代理配置影响，生产系统需要可信代理和集中限流。
- PBKDF2 参数需要随硬件和安全基线定期评估。
- POC 协议没有标准生态审计和互操作保证，不能开放给第三方客户端。
- 当前不具备 MFA、密码生命周期、账号恢复和集中安全运营能力。

这些限制不能通过增加少量代码消除；正式发布前必须完成 Keycloak/OIDC 集成和独立安全评审。
