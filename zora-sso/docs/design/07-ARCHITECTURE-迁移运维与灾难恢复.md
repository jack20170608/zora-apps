# 迁移、运维与灾难恢复

**状态：目标设计，尚未实施。**

## 1. 分阶段迁移

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| 1. 基础设施 | 非生产 Keycloak、数据库、TLS、Secret 管理 | 可重复部署并完成备份恢复 |
| 2. OIDC 核心 | Discovery、Code + PKCE、Token 校验、身份映射 | 安全负向测试全部通过 |
| 3. 单应用试点 | 一个低风险应用接入 | 登录、登出、审计和回滚稳定 |
| 4. 批量迁移 | Client 模板、接入手册、监控面板 | 关键应用完成迁移 |
| 5. POC 下线 | 删除本地用户、私有端点和绕过配置 | 无流量、无依赖、数据已安全清理 |

迁移期间不能让同一账号在两个体系中被静默合并。建立明确的外部主体映射，并准备逐应用回滚开关；回滚不能绕过认证。

## 2. 可观测性

最低指标：

- 登录成功率与按稳定错误码分类的失败率；
- Token Endpoint、Discovery、JWKS 延迟和错误率；
- 活跃会话、创建和撤销数量；
- 限流、账号锁定、MFA 失败和异常来源；
- Keycloak 节点、数据库连接池、缓存和 JVM 指标。

日志使用关联 ID 串联应用与身份服务事件，但不得记录密码、Cookie、Code、Token、Secret 或完整敏感 Claims。

## 3. 密钥与 Secret 轮换

轮换必须先增加新密钥，再等待所有验证方取得新 JWKS，之后切换签名，最后在旧 Token 最大生命周期结束后移除旧密钥。Client Secret 使用双版本重叠或逐 Client 轮换，不能一次替换全部客户端。

每次轮换记录负责人、时间、受影响 Client、验证结果和回滚条件。

## 4. 故障策略

| 故障 | 默认行为 |
|---|---|
| Keycloak 暂时不可用 | 已有本地 Session 按既定期限工作；新登录失败 |
| JWKS 刷新失败 | 在受控陈旧窗口内用缓存；超窗后拒绝新 Token |
| Session 存储不可用 | 拒绝创建或验证会话，不创建降级身份 |
| 数据库故障 | Keycloak 停止写入或服务，按平台恢复流程处理 |
| 时钟异常 | 告警并拒绝超出容差的 Token |

“可用性降级”只能复用已经验证且未过期的安全状态，不能跳过签名、Claims 或权限检查。

## 5. 备份与恢复

- 明确数据库、Realm 配置、密钥和 Secret 的恢复责任。
- 备份加密、异地保存并限制访问。
- 定期执行恢复演练，而不是只检查备份任务成功。
- 恢复后验证 Issuer、Client、密钥版本、用户状态和审计连续性。
- 定义 RPO、RTO，以及恢复后是否强制全局会话失效。

## 6. POC 退役清单

1. 所有应用停止调用 `/authorize`、`/login` 和 `/token/exchange` 私有接口。
2. 删除本地用户密码哈希与 Client Secret 哈希。
3. 移除 `local-auth.production-allowed` 及本地认证启动路径。
4. 删除内存 Session、事务和 Code 实现。
5. 保留必要审计记录，清理不再需要的敏感配置和备份。
