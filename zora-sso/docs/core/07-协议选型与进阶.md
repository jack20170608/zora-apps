# 协议选型与进阶

## 1. 常见选择

| 场景 | 优先考虑 |
|---|---|
| 现代 Web、移动端和 API | OIDC + OAuth 2.0 |
| 传统企业联合身份 | SAML 2.0 |
| 企业目录查询 | LDAP；它不是浏览器 SSO 协议 |
| 同一安全域内的旧式集成 | Kerberos/SPNEGO，需专门运维能力 |

对新建 Zora 应用，默认选择成熟身份提供方提供的 OIDC，不自行实现协议端点和 Token 签发。

## 2. 自建与集成

自建身份提供方意味着长期承担：

- 协议兼容性和安全更新；
- 密码、MFA、恢复和账号生命周期；
- 密钥托管、轮换和灾难恢复；
- 会话、撤销、审计与异常检测；
- 第三方安全评审与合规。

因此 `zora-sso` 的生产目标是**集成 Keycloak 等成熟 Provider**，而不是把当前 POC 扩展成完整 OIDC Provider。

## 3. 推荐能力边界

`zora-sso` 可以负责：

- 封装 Zora 应用统一的 OIDC Client 接入；
- 严格 Token 校验；
- 外部身份到本地身份、角色的显式映射；
- 应用 Session 与统一审计模型；
- Provider 配置、健康检查和可观测性。

身份提供方负责：

- 用户认证、MFA 和账号恢复；
- 标准协议端点与 Token；
- 中央会话、联合身份和密钥发布；
- 管理控制台和安全策略。

## 4. 进阶学习顺序

1. 阅读 RFC 9700，理解 OAuth 安全最佳当前实践。
2. 手工抓取一次 OIDC Code + PKCE 流程，逐项关联本地事务状态。
3. 实现并测试严格的 ID Token / Access Token 校验器。
4. 研究 RP-Initiated Logout、Back-Channel Logout 和 Token Revocation。
5. 设计多节点会话、密钥轮换、故障模式和审计告警。
