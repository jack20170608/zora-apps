# 威胁模型与安全基线

## 1. 从资产和边界开始

先识别资产：用户凭据、会话、授权码、Token、客户端凭据、签名密钥、审计记录。再标出浏览器、反向代理、业务应用、身份提供方和外部网络之间的信任边界。

安全设计不能只列攻击名称，必须为每个威胁明确控制措施、验证方法和剩余风险。

## 2. 核心威胁

| 威胁 | 关键控制 |
|---|---|
| 登录 CSRF / 响应注入 | 随机、一次性、绑定会话的 `state` |
| 授权码截获 | Authorization Code + PKCE，短 TTL，一次性兑换 |
| OIDC 重放 | `nonce` 与本地授权事务绑定 |
| 开放重定向 | 回调 URI 预注册并完整匹配 |
| Session 固定 | 认证成功和权限提升后轮换 Session ID |
| Token 误用 | 校验签名、`iss`、`aud`、时间和 Token 类型 |
| 凭据填充 | 分层限流、MFA、风险检测，避免用户名枚举 |
| XSS 窃取凭据 | CSP、输出编码、HttpOnly Cookie、减少浏览器 Token 暴露 |
| CSRF 修改状态 | SameSite Cookie + CSRF Token + Origin/Referer 策略 |
| SSRF / 恶意 JWKS | 预配可信签发者，限制出站请求、超时、大小和重定向 |
| 日志泄漏 | 不记录密码、Cookie、Code、Token、密钥和完整敏感 Claims |

## 3. `state`、`nonce`、PKCE 不能互换

- `state` 关联客户端发起的浏览器事务与回调。
- `nonce` 关联 OIDC 请求与 ID Token。
- PKCE 证明兑换授权码的是发起请求的客户端实例。

三者保护不同边界。协议要求使用时必须分别生成、保存、绑定、比较和单次消费。

## 4. 凭据与密钥

- 密码使用适合密码的 KDF，并按组织基线调参；不能使用普通 SHA 哈希。
- 客户端密钥和签名私钥进入专用 Secret 管理系统，不进入仓库和普通配置日志。
- 制定轮换周期、重叠窗口、回滚和紧急吊销流程。
- 比较秘密时使用恒定时间函数。

## 5. 安全失败语义

以下情况必须拒绝请求：

- 签名或必要 Claims 无法验证；
- Discovery/JWKS 来自未受信地址；
- 授权事务缺失、过期或已消费；
- 回调地址不完全匹配；
- 身份映射冲突；
- 权限映射未配置；
- 认证依赖超出允许的陈旧或不可用窗口。

错误响应避免泄露账号是否存在、密钥轮换细节和内部异常。服务端日志保留关联 ID 与稳定错误码，不记录秘密。

## 6. 上线检查

1. 完成数据流图和威胁模型。
2. 对协议库和配置做独立安全评审。
3. 覆盖篡改、重放、过期、错误受众、未知密钥和开放重定向测试。
4. 验证代理、TLS、Cookie 和来源地址配置。
5. 演练密钥轮换、身份提供方故障和紧急会话撤销。
